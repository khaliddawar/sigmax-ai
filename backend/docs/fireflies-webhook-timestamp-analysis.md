# Fireflies Webhook Timestamp Analysis

## Summary

**Key Finding**: Fireflies webhook payloads do **NOT** include any timestamp information directly in the webhook payload itself.

## Actual Fireflies Webhook Payload Structure

Based on official Fireflies documentation, the webhook payload contains only:

```json
{
    "meetingId": "ASxwZxCstx",
    "eventType": "Transcription completed", 
    "clientReferenceId": "be582c46-4ac9-4565-9ba6-6ab4264496a8"
}
```

## Timestamp Information Sources

### 1. **Webhook Received Timestamp** (Our Server)
- **What**: When our server receives the webhook
- **Source**: Generated by our application (`webhook_received_at`)
- **Format**: ISO 8601 UTC timestamp
- **Purpose**: Audit trail of when we were notified

### 2. **Meeting/Transcript Timestamp** (From Fireflies API)
- **What**: When the actual meeting occurred
- **Source**: Must be fetched via Fireflies GraphQL API using the `meetingId`
- **Available Fields**:
  - `date`: Unix timestamp in milliseconds from EPOCH
  - `dateString`: ISO 8601 format (e.g., "2024-04-22T20:14:04.454Z")
- **Purpose**: Actual meeting timing for business logic

## Implementation in Our System

### Current Webhook Handler
```python
# 1. Record when WE received the webhook
webhook_received_at = datetime.now(timezone.utc).isoformat()

# 2. Create normalized payload
normalized_payload = {
    "transcript_id": meeting_id,
    "meeting_id": meeting_id,
    "event_type": event_type,
    "client_reference_id": client_reference_id,
    "webhook_received_at": webhook_received_at,
    # Note: meeting_timestamp will be fetched from Fireflies API
}
```

### Required Next Steps
1. **Fetch Meeting Data**: Use Fireflies GraphQL API to get actual meeting timestamp
2. **Store Both Timestamps**: 
   - `webhook_received_at`: When we got notified
   - `meeting_date`: When the meeting actually occurred
3. **Use Correct Timestamp**: Use `meeting_date` for business logic, `webhook_received_at` for audit

## GraphQL Query to Fetch Meeting Timestamp

```graphql
query GetMeetingTimestamp($meetingId: String!) {
  transcript(id: $meetingId) {
    id
    title
    date          # Unix timestamp in milliseconds
    dateString    # ISO 8601 format
    duration
    organizer_email
  }
}
```

## Why This Matters

1. **Email Subject Lines**: Need actual meeting date for "Recap - June 9, 2025" format
2. **Database Storage**: Proper chronological ordering of transcripts
3. **Anti-Hallucination**: Timestamp validation requires actual meeting duration
4. **Audit Trail**: Distinguish between when meeting happened vs when we processed it

## Recommendations

1. **Always fetch meeting data** from Fireflies API after receiving webhook
2. **Store both timestamps** for complete audit trail
3. **Use meeting_date** for all business logic and user-facing features
4. **Use webhook_received_at** only for system monitoring and debugging
